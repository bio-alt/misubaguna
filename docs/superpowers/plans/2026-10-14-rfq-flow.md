# Product-aware Quote Request (RFQ) Flow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A dedicated `/request-a-quote/` page that knows the product, asks its checklist, accepts drawings, stores every request with a `Q-` reference, emails sales and the buyer, and works under `/id/`.

**Architecture:** One `inquiries` table (`kind` = quote|contact) and `Inquiry` model. A `QuoteRequest` support class owns link building, product lookup and checklist resolution so GET and POST derive identical labels. `QuoteRequestController` serves form/store/thanks/file-download for both locales; two mailables send the internal and confirmation emails. Existing "Request a quote" links are rewired through `QuoteRequest::url()`.

**Tech Stack:** Laravel (PHP), Blade, PHPUnit feature tests (SQLite in-memory, `Mail::fake`, `Storage::fake`), `public/css/catalog.css`.

**Spec:** `docs/superpowers/specs/2026-10-14-rfq-flow-design.md`

## Global Constraints

- Follow the career form pattern (`CareerController@store`): store first, mail second, mail failures `report()`ed and never shown to the quote buyer.
- Reference format `Q-YYYY-XXXXXX` (random 6-char suffix, unique retry), same approach as `EjmaCalculation::nextReference()`.
- Files: max 3, each `max:10240` KB, extensions pdf, dwg, dxf, jpg, jpeg, png, xlsx, docx; stored on `local` disk at `inquiries/YYYY/MM/{Str::random(24)}.{ext}`; original names trimmed to 180 chars.
- Attach files to the internal email only when their total size ≤ 15 MB (15 × 1024 × 1024 bytes); signed download links valid 60 days always listed.
- Field limits: name 120, company 160, email 160, phone 40, location 160, item 160, each answer 500, message 5000 (GET `message` prefill truncated to 2000).
- Quote and thank-you pages: `robots_index=false`, `robots_follow=true`, canonical, BreadcrumbList; not added to sitemap or llms.
- Design: `catalog.css` tokens (teal `#176b70`, ink `#10202a`, mist `#edf3f3`), compact type, no `<header>` element inside page content, no red/orange.
- All UI copy through `__()`; Indonesian strings in `lang/id.json`. No promised turnaround times, prices or stock.
- "At least one" error copy (exact): `Please answer at least one question, attach a drawing, or describe what you need.`
- Run tests with `php artisan test` (whole suite must stay green).

## Review Focus

1. Tampered `answers[]` indices (e.g. `answers[99]`, or answers posted for a product whose checklist is shorter) — extra indices are silently dropped, labels always come from the server checklist. → Task 5 test `test_tampered_answer_indices_are_ignored`.
2. Hostile `item`/`message` query strings (`<script>`, 500-char item) — rendered escaped and truncated to 160/2000. → Task 3 test `test_prefill_is_escaped_and_truncated`.
3. Indonesian or unusual file names (`Gambar teknik—rev 2 (final).pdf`, 300 chars) — stored under random name, original kept (trimmed 180), download serves the original name. → Task 4 test `test_download_uses_original_file_name`.
4. Indonesian submit round-trip — POST to `/id/request-a-quote/` redirects to `/id/request-a-quote/thanks/{ref}`, stores `locale=id`, confirmation mail rendered in Indonesian. → Task 5 test `test_indonesian_submit_stays_in_indonesian`.
5. Product unpublished between page view and submit — the request is still stored as a generic quote (default checklist labels, `product_slug` null) rather than failing. → Task 5 test `test_unpublished_product_falls_back_to_generic`.
